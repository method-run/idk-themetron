# Playground

<!-- idk-plans:progress:start (generated) -->
◐ 88% (8/9)
<!-- idk-plans:progress:end -->

The playground is a web page with the inputs on the left and the result on the right. Each change rebuilds the themes at once.

- **Themes:** one card for each theme, indented under its parent. The title bar shows the theme's name, kind, parent, and action ramp, with a remove button. Open a card to edit that theme, and the preview shows it. The Name field takes any text, such as "USA" or "Big Sale". The playground shows that text as the theme's label, and makes the theme's name for code from it: `usa`, `big-sale`. The hint under the field shows the class. A theme without its own label shows its name with a capital letter, such as "Warning". The Contrast section chooses WCAG 2 or APCA. Every theme ships both levels: the standard one, and the enhanced one for readers who ask for more contrast. The Contrast switch in the View menu shows the second. In order, a card has Contrast, Base color, Action color, Typography, Icons, Animation, and Feel, with a line between each. In Action color, "+ Gradient" adds a second color. The gradient picker shows the two colors, a chip under the bar that sets the solid color, and an angle fader. "Make it solid" removes the second color. In Icons, a three-stop slider sets the corners (sharp, standard, or rounded), and two more controls set the fill and the weight. The preview's Icons section has a search field that lists every icon. A child shows only the sections that it overrides: "Override" adds one, and × removes it, so the child takes it from its parent again. Fonts start as the browser's own sans-serif and monospace fonts, and the heading font is the same as the body font. Solid fills always have light labels in light mode, and dark labels in dark mode. The sample also shows inverted parts, with `class="tm-invert"`. A child that sets only colors is a color theme. In Typography, each font role is a Google font picker, and the Type variance slider sets how fast headings grow. Type variance is not a feel, so presets do not set it. An empty field shows, in gray, the font that the role uses now. × clears the theme's own font. "Browser default", the first suggestion, turns off a parent's web font in a child. "Your own font…", the second, opens a dialog for a font file. The dialog wears the selected theme, so it is a sample of the dialog, field, file, segmented, alert, and button parts too. Link takes the URL of a file on any site. The site must let other sites load the file (CORS); if it does not, the note under the font field says so. Edit in the note opens the dialog again. Upload takes a file from your computer. The file stays in this browser, in IndexedDB, and the preview uses it. The export loads it from a path on your site, such as `/fonts/my-font.woff2`, so put the file there. A share link has the path, not the file. "Apply a preset" is a one-time stamp: it opens a list of presets, and picking one sets every feel as the theme's own, and the animation, and stores nothing else. The theme keeps no link to the preset. The last item, "I feel lucky", sets every feel to a random value in the same way. A spider chart under the preset note shows the feels, one spoke each, with short labels: Round, Space, Depth, Soft, Thin, Shine, Clear, Play, and Energy. Drag a node along its spoke, or focus it and use the arrow keys. The sliders are under "Adjust the feels", which opens by itself when the feels match no preset. Then each feel is like a font or a color: while it is the theme's own, its node on the chart is filled, its label has a dot, and its slider has a ×. × takes it from the parent again (for the root, the default). The note under the button says "Matches Glass" when the feels match a preset exactly, and "Custom" when they do not, and the list marks the match with ✓. Brutalist with its parent's sizes is: apply Brutalist, then × on Space. Each section heading opens and closes the section, for every theme at once, and the page remembers it. "Override" adds a section, opens it, and scrolls to it. Each card shows in its own theme: its colors, its font, and its color on the choice controls, in the page's light or dark mode. Each card ends with "+ Add a child of *name*", which adds a child of that theme and opens it. The new child takes the first name from the [semantic theme names](../spec/inputs.md#theme-names-to-start-with "inputs") that is not taken yet: danger, warning, success, info, then secondary, each with a suggested color. After those, it is Child 1, Child 2, and so on. The list is a tree: each theme's children come right after it. Drag a card by its grip (six dots, at the right of its bar) or anywhere on its bar to move a theme, with its children: drop it on the top or bottom edge of another card to put it before or after that theme, or on the middle to make it a child. A line or an outline shows where it goes, and an open card folds while it moves. A theme cannot go into its own children, and the root does not move. From the keyboard, focus a grip and press Space to lift the theme: Up and Down move it past its siblings, Right puts it in the theme above, and Left moves it out, after its parent. Space drops it, and Escape puts it back. A screen reader hears each step. The Parent field nests a theme too. Delete a theme at the bottom of its open card: its children move up to its parent.
- **Theme sets:** you can keep a few theme trees at once, each a theme set with its own name, and switch between them with the Theme set field. "+ New set" starts one from the default theme, "Copy this set" copies the open one, and "Delete this set" asks first. The sets are in this browser's localStorage, so download a set's inputs from the Tokens view to keep it. "Import a set…" opens an inputs file as a new set, so a set can move to another browser. The new set takes its name from the file: `new-themes-inputs.json` becomes "New themes". A share link opens as a new set, "Shared themes", so it does not replace the open one. Downloads take the set's name as a name for code, such as `admin-app.css`, and each export's first line names the set and the token contract.
- **View menu:** the View button above the output holds the mode (light, dark, or both), the contrast variant (base or more contrast), the themes that the preview shows, the grid, and the photo backdrop.
- **Preview:** the sample page, in the modes that the View menu picks. It shows the open theme. Under the buttons, two collapsible rows: "Inverted" shows the normal, soft, and exact buttons with `class="tm-invert"`, and "Descendant themes' buttons" shows the button of each theme below the open theme, in tree order, on its background. To compare other themes, pick more themes in the View menu, or All. "Photo backdrop" in the same menu puts a photo behind the samples, colored with each theme's ramps, so you can see what shows through see-through parts at high clarity. Its sliders set the hue (from the base ramp to the action ramp), the blur, the contrast, and the brightness. The samples then use `tm-over-media`: see-through parts blur the photo, and text gets a halo. Then a Compare section shows a button and a card in each theme, one row for each mode. "Side by side" puts the themes in a row. "Nested" puts each child's zone inside its parent's zone. Each zone has only its own theme class, as on a real page. A theme class sets every token from the tree, so a theme looks the same in its zone wherever the zone is. Below it, each theme has its own section with the whole sample. Each section can collapse. "Follow the open theme" goes back to one theme.
- **Motion:** the Animation section of a card chooses None, Fade, or Move, and the Play and Energy feels tune it. The sample's Motion section shows it: a dialog, a sidebar, a toast, a menu, tabs with a sliding underline, a switch, a list that staggers in, and a field that shakes.
- **Palettes:** each theme's ramps, in tree order: its own base ramp, if it sets one, then its action ramp. Also the grade gaps. There is one panel for each mode, on that mode's canvas. Each chip shows only its grade number. Point at it to see its hex value and the tokens that use it in that mode. Select two chips to compare them.
- **Tokens:** the themes as a ready-to-use **Stylesheet** (the tokens and the components in one file), CSS tokens, DTCG JSON, Tailwind, **shadcn/ui** variables, an **MUI** theme, **daisyUI** themes, or **Bootstrap** variables (Sass or CSS), and the inputs as JSON. For Bootstrap CSS, "Preview on Bootstrap 5.3" opens Bootstrap's stock parts with the export, in light and dark mode, and a row for each child theme. It runs in a frame, so Bootstrap's CSS does not reach the playground, and Bootstrap loads only when you open it. A line under the formats says how to use each one. **Download** saves the format on screen as a file. In the Inputs view, **Open file…** loads inputs from a `.json` file. The Light, Dark, and Both switch does not apply here, because every format holds both modes. You can copy each one, and paste inputs to load them.
- **Copy share link**, at the top right, copies a link that holds the themes, compressed. Opening it loads them, and then takes them out of the address.
- **Audit:** every checked pair, with its WCAG ratio, APCA value, and result.

There are two ways to run it:

- `npm run dev` starts the Vite dev server at `http://localhost:4321/` and opens the playground. A change to the components shows at once. A change to the engine reloads the page.
- `npm run build` builds the documentation site with the playground in it. Then `npm run preview` serves it at `http://localhost:4321/`. `npm run plans:preview` does both. The playground is at `play/`.
- If port 4321 is in use, Vite tries the next port and prints the address. `npm run dev -- --port 5000` starts at another port.

**Grid ·** in the View menu, or the period key, shows the rhythm grid over the preview: faint lines every rhythm step, down and across. On wide screens, the inputs and the output scroll on their own. Drag the line between them to change the width of the inputs, or focus it and use the arrow keys. The chevron button at the top left of the output, labeled "Hide inputs" or "Show inputs" for screen readers, gives the output the whole width. The page remembers both in the browser.

<details>
<summary>How it works</summary>

- Vite serves and builds only the playground. Its settings are in `vite.config.js`. `demo/demo.js` imports the engine from `src/` and the styles from `components/`. The engine itself has no build step and no dependencies.
- `npm run build` builds the docs with idk-plans into `_site/`. Then `vite build` bundles the playground into `_site/play/`. Last, `scripts/build-site.js` adds links between the docs and the playground. Any static host can serve `_site/`.
- The page keeps your inputs in the browser's local storage. Nothing leaves the browser, except requests for Google Fonts and for font files that you link to. Uploaded font files stay in the browser's IndexedDB.
- Links open a view: `#palettes`, `#tokens`, `#audit`. `?preset=glass` opens the page with a preset.

</details>
